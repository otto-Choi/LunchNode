# TMT 준비 상태

본부 표시명은 **TMT**, 초대 코드는 **TMT36**으로 예정합니다.
로그인 본부 선택에 `TMT · 준비 중`이 나타나며, 명단 확인 전에는 API에서도 입장을 차단합니다. 환경변수를 먼저 넣어도 열리지 않습니다.

## 확정된 설계

- 기존 Supabase 프로젝트 안에서 `tmt_lunch_*` 테이블과 RPC로 AX/Global과 분리합니다.
- 별도 `tmt_lunch_session`, `tmt_lunch_roster` 쿠키와 TMT 전용 토큰 해시를 사용합니다.
- Global과 같은 편성 기준: 필수 메뉴 준수 → 반복 만남 회피 → 두 팀 혼합 → 메뉴 선호. 성비는 사용하지 않습니다.
- 기본 신청 상태는 미선택, 메뉴는 상관없음이며 12월 입사자 기본 불참 규칙은 적용하지 않습니다.
- 운영 시각은 전날 22시 최초 편성, 당일 11시 마감으로 유지합니다.
- Group Node는 전체 본부 모임에 참여하고, TMT 전용 모임도 지원하도록 확장합니다.

## 명단을 받은 뒤 할 작업

1. 두 팀의 정확한 이름과 이름별 소속을 받아 `lib/backend/tmt-roster.ts`에 고유 ID와 함께 등록합니다. 동명이인 여부를 확인합니다.
2. 실제 운영 시작일과 종료일을 확인합니다. 기존 운영 종료일(2026-11-30)을 이미 지났다면 그대로 복제하지 않습니다.
3. Global의 검증된 RPC를 기반으로 TMT 전용 SQL 마이그레이션을 생성합니다. Global/AX 명단, 상태, 계정은 복사하지 않습니다.
4. Group Node의 본부 CHECK 제약, 세션 검증, 명단 조회 함수를 TMT까지 확장합니다. 현재 운영 DB는 아직 AX/Global만 지원합니다.
5. `TMT_INVITE_CODE=TMT36`과 다른 본부와 중복되지 않는 32자 이상 `TMT_ADMIN_SECRET`을 서버 환경변수로 설정합니다. 관리자 키는 공개하지 않습니다.
6. 본부별 초대 코드·운영자 키 중복 검증과 TMT 예약 작업을 추가하고 준비 중 차단을 해제합니다.
7. 실제 PostgreSQL에서 등록/로그인/신청/편성/복구 및 Group Node 본부 간 권한과 데이터 격리를 검증한 뒤 배포합니다.

현재는 준비 단계이므로 운영 DB 마이그레이션이나 환경변수 변경을 하지 않습니다. 기존 AX/Global 데이터는 그대로 유지합니다.
