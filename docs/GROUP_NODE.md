# Lunch Node + Group Node

## 서비스

- **Lunch Node**: 기존 주황색 점심 일정·편성·기록. AX Node와 Global은 기존대로 분리합니다.
- **Group Node**: 하늘색 소모임. 기존 계정의 본부·실명을 사용하며 다시 가입하지 않습니다.
- 상단에서 서비스를 전환합니다. PC는 왼쪽 메뉴, 모바일은 상단 메뉴 버튼으로 여는 왼쪽 패널을 사용합니다. 메뉴는 Escape·닫기·바깥 영역 클릭·메뉴 선택으로 닫힙니다.
- 소모임 하위 메뉴: 모임 둘러보기 / 내 모임 / 지난 모임. 모임 만들기는 별도 버튼입니다.

## 소모임 동작

카테고리는 등산·보드게임·스포츠·맛집·기타입니다. 최소 인원은 2~40명이며 후보 날짜는 1~5개, 시간은 선택 사항(10분 단위)입니다. 주말도 후보로 지정할 수 있습니다.

전체 본부 모집은 AX Node·Global 모두 조회·참여·투표·댓글 작성이 가능합니다. 우리 본부 전용은 다른 본부의 목록·상세·참여·투표·댓글에서 모두 차단됩니다. 타 본부의 참여·댓글이 이미 있으면 전체 모집을 본부 전용으로 좁힐 수 없습니다.

생성자는 자동 참여하며, 참여자는 가능한 날짜를 여러 개 선택할 수 있습니다. 최소 인원 충족은 날짜 확정과 구분합니다. 모임장만 날짜를 확정하며, 참여 취소로 최소 인원보다 줄어들어도 확정 날짜는 유지하고 부족 안내를 표시합니다. 참여 취소는 해당 인원의 투표를 함께 삭제합니다.

후보 날짜·시간 변경 시 그 후보의 표만 초기화하고, 후보 구성이 바뀌면 날짜 확정을 해제합니다. 확정 날짜가 지난 모임(미확정이면 마지막 후보 날짜가 지난 모임), 취소된 모임은 지난 모임에서 확인합니다. 지난 모임에서는 새 참여·취소·투표를 막고 댓글을 이용할 수 있습니다.

수정·삭제·날짜 확정·모집 재개·취소는 모임장만, 댓글 삭제는 작성자만 가능합니다. 모든 판정은 서버·DB에서 수행합니다. 화면 갱신은 소모임 화면이 열려 있을 때 15초 간격과 창 포커스 복귀 시 실행합니다. 검색·카테고리·본부 필터를 제공하고 목록은 20개 단위로 표시합니다.

## 구조와 보안

새 테이블은 같은 Supabase 프로젝트의 `group_node_meetups`, `group_node_dates`, `group_node_participants`, `group_node_votes`, `group_node_comments`입니다. 기존 점심 테이블을 수정하지 않습니다. 본부·사용자 ID 조합으로 사람을 구분해 본부 간 ID 충돌도 방지합니다.

브라우저 → `/api/group-node` → 서버의 기존 세션 해시 → 서비스 전용 `group_node_api` → 비공개 스키마의 검증된 DB 함수 순서로 처리합니다. 브라우저가 보내는 작성자 ID는 신뢰하지 않습니다. 기존 PIN 변경·운영자 세션 해제는 소모임에도 적용됩니다.

모든 새 테이블에 RLS를 켜고 anon·authenticated·service_role의 직접 테이블 접근은 차단합니다. 비공개 함수는 고정된 빈 search_path를 사용합니다. 서비스 전용 API에만 실행 권한을 주며 DB에서도 매 요청 기존 본부 세션을 확인합니다. 같은 모임의 쓰기는 행 잠금으로 직렬화하고 모임장 편집·삭제·확정에는 버전 검사를 적용합니다. 생성과 날짜 저장, 날짜 수정·투표 초기화는 하나의 트랜잭션입니다.

DB 설치 파일: [`supabase/migrations/20261026124241_group_node.sql`](../supabase/migrations/20261026124241_group_node.sql). Supabase CLI의 `migration new group_node`로 초안을 생성한 뒤, MCP로 운영에 적용된 버전 `20261026124241`에 파일명을 동기화했습니다. 기존 DB 또는 신규 `schema.sql` 설치 후 이 추가 마이그레이션을 한 번 적용합니다. 새로운 환경변수는 필요 없습니다.

## 원본 앱

2026-10-26 전달받은 `dongi-somoim-handoff.zip`의 화면 흐름·카테고리·참여·투표·댓글 기능을 기반으로 런치노드의 Next.js·세션·DB 권한 모델에 맞춰 통합했습니다. Vite 앱을 iframe으로 삽입하거나 원본의 공개 쓰기 정책을 복사하지 않습니다.

ZIP에는 실제 모임·댓글 데이터 내보내기 파일과 원본 DB 접속 설정이 없습니다. 원본 서비스와 DB는 유지하며, 기존 모임을 옮길 경우 소모임 개발자가 제공하는 데이터 내보내기와 닉네임→본부·실명 매핑을 검토해 별도로 이관합니다.

## 검증

`tests/group-node.test.cjs`: 입력 검증, 세션과 본부 바인딩, 작성자 위조·CSRF 차단.

`tests/database.test.mjs`: 실제 PostgreSQL에서 본부 간 공유·전용 모임 차단, 참여·투표·댓글 권한, 확정·수정 충돌, 후보 변경 시 투표 초기화, 참여 취소 시 투표 제거, 직접 DB 접근 차단, 점심 상태 보존을 검증합니다.

`tests/browser/group-node.spec.ts`: PC·모바일에서 생성→타 본부 참여→투표→댓글→모임장 확정→내 모임→서비스 전환→삭제와 모바일 메뉴를 확인합니다. 기존 점심 브라우저 QA도 함께 실행합니다.

## 운영 적용 기록 · 2026-10-26

공통 Supabase 프로젝트에 추가 마이그레이션을 적용했습니다. 적용 직전·직후 AX 계정 18개와 Global 계정 20개, 각 본부의 점심 상태 버전·전체 상태 체크섬이 일치했습니다. 새 5개 테이블의 RLS와 서버 전용 API 실행 권한을 확인했습니다. 보안 Advisor의 WARN/ERROR는 없고, INFO 수준의 RLS 정책 없음은 직접 테이블 접근을 차단하고 검증된 서버 RPC만 사용하는 의도된 구성입니다. [해당 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

새 API·UI 코드에 대해 단위 테스트 82개, PostgreSQL 통합 테스트 14개, PC·모바일 브라우저 테스트 30개가 통과했습니다. 타입 검사·프로덕션 빌드·운영 의존성 검사도 통과했습니다. 최종 main CI는 공개 운영 주소의 본부 목록·로그인 필요 상태·Group Node 인증 차단도 읽기 전용으로 확인합니다.
