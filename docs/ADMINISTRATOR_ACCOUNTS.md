# 본부별 관리자 계정

AX Node, Global, TMT 로그인 이름 목록의 맨 아래에 `관리자`가 표시됩니다.
각 계정은 미리 생성되어 있으므로 초대 코드 확인 후 로그인합니다. 일반 최초 등록으로 관리자 계정을 만들거나 권한을 얻을 수 없습니다.
초기 PIN은 운영자가 지정한 동일한 값으로 설정하되, 서버에서 생성한 scrypt 해시만 저장하고 원문은 저장소·브라우저 코드에 넣지 않습니다.

## 권한

- 각 본부 운영자 도구를 별도 운영자 키 입력 없이 사용합니다. 기존 운영자 키 인증 방식도 유지합니다.
- Group Node는 한 명의 운영자가 통합 관리합니다. 모든 본부의 공개·전용 글을 조회·수정·삭제·전환하고 날짜 확정·모집 재개·참여자 추가를 실행할 수 있습니다.
- 타인 댓글의 수정·삭제도 지원합니다. 댓글 수정은 이전 내용을 비교해 동시 수정 덮어쓰기를 막습니다.
- 글 작성자와 본부 표시를 관리자 정보로 바꾸지 않습니다. 본부 전용 글의 참여자 추가는 그 글의 소속 본부 인원으로 제한합니다.
- 일반 사용자에 대한 다른 본부 전용 글 차단과 작성자/댓글 소유자 검증은 유지합니다.

관리자 역할은 DB 고정 명단의 `is_admin`으로 판별하며 이름이나 클라이언트가 보내는 플래그를 신뢰하지 않습니다.
관리자도 본부 초대 코드·PIN·본부별 세션 검증을 거칩니다. 한 본부의 토큰을 다른 본부 로그인에 재사용할 수 없습니다.

## 참가자 제외와 보존

관리자 행은 별도 역할로 명단·계정 테이블에 추가합니다. 기존 직원 UUID·PIN·세션·신청·편성 기록은 변경하지 않습니다.
참가자 스냅샷·인원 통계·편성·참여자 추가 목록에서는 관리자 행을 제외합니다.
관리자는 점심 신청이나 모임 참여/투표를 하지 않고 관리 기능을 사용합니다. 관리자가 쓴 모집글도 자동 참여자로 집계하지 않습니다.
Group Node 관리 작업은 접근 제한된 비공개 스키마의 감사 기록에 남습니다.

## 설치

persistent_clubs 다음에 headquarters_administrators 마이그레이션을 적용합니다.
마이그레이션은 초기 잠금 상태의 관리자 계정을 생성하며, 실제 PIN은 서버에서 해시를 생성해 계정별로 최초 한 번 설정합니다.
이미 설정되거나 변경된 PIN은 마이그레이션 재실행으로 덮어쓰지 않습니다.
단위·실제 PostgreSQL·PC/모바일 테스트로 로그인, 역할 위조 차단, 운영 도구, 타 본부 비공개 글 관리, 직원 데이터 보존을 검증합니다.
