Group Node의 생성·참여·투표·댓글·본부 범위·소유자 권한, 빌드/의존성/배포 검증을 확인했습니다.

## 수정 사항

- 세 본부의 고정 종료일 및 140일 상한을 제거합니다. 종료일 NULL에 대응하도록 조회·신청·재편성 SQL을 함께 수정합니다.
- 무한한 미래 날짜를 생성하지 않도록 앞으로의 사전 신청 범위를 매월 자동으로 늘립니다.
- 이미 확정된 날짜는 반복 조회 때 기본값을 다시 채우지 않습니다. 과거 선택과 조를 보존하고 불필요한 연산을 줄입니다.
- 모바일에서는 지난 날짜 카드를 DOM에 만들지 않습니다. PC 월별 달력과 과거 기록은 유지합니다.
- 운영자 감사 이력의 사용자 외래키와 소모임 날짜별 투표 조회에 필요한 인덱스를 추가합니다.
- 소모임 목록에서 페이지에 표시할 20개를 먼저 골라 참여자·투표를 계산하도록 수정합니다.
- 가입 거절 안내의 고정 인원수 20명을 제거해 TMT 18명에도 맞게 표시합니다.
- Group Node의 본부 안내와 모집 범위에서 누락된 TMT를 반영합니다.

## 유지하는 동작과 한계

초대 코드를 확인한 브라우저는 본부별 인증을 7일, 로그인 세션은 최대 21일 유지합니다.
로그아웃 후에도 코드 확인 기록이 남는 것은 현재 인증 정책입니다. 새 브라우저에는 초대 코드가 필요합니다.
식사 방식 필수 조건과 조 인원 구성을 먼저 만족시킨 뒤 과거 만남과 본부별 혼합 기준을 적용하므로,
참석 규모와 필수 메뉴에 따라 같은 사람을 다시 만나거나 팀 비율이 완전히 같지 않은 조가 생길 수 있습니다.

기존 상태는 본부별 단일 JSON 문서에 과거 기록을 계속 보관합니다. 현재 규모에서는 동작하지만 장기간 운영으로
데이터가 크게 늘면 일자별 기록/누적 만남 집계로 분리하는 후속 최적화가 필요합니다. 이번 작업에서는 과거 기록을 삭제하지 않습니다.
운영 DB를 변경하는 기능 QA는 별도의 폐기 가능한 PostgreSQL에서 실행하며, 운영에서는 데이터 보존과 읽기 전용 상태만 확인합니다.

## DB 성능 진단

Supabase가 안내한 감사 이력 6개와 날짜별 투표 1개 외래키의 인덱스를 보완합니다.
모임의 확정 날짜 외래키 `(id, confirmed_date_id)`는 기본키 `id` 조회로 후보가 이미 최대 한 행이므로 중복 복합 인덱스를 추가하지 않습니다.
[미색인 외래키 진단 기준](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys)을 참고했습니다.
사용량이 적어 아직 사용되지 않은 세션 인덱스는 PIN 변경·세션 취소 시 필요하므로 삭제하지 않습니다.
