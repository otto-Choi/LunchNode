# DEAL 본부 준비

본부 ID는 `deal`, 표시 이름은 `DEAL`, 초대코드는 `DEAL36`입니다.
명단을 받기 전에는 로그인 본부 목록에 `DEAL · 준비 중`으로 표시합니다.
환경변수가 있어도 명단이 비어 있으면 가입·조회·운영자 도구·Group Node 접근을 차단하고 예약 작업에서 제외합니다.
기존 세 본부의 데이터·계정·코드는 변경하지 않습니다.

## 준비된 항목

- 본부 식별자, 로그인 목록, 빈 `DEAL_ROSTER`, 전용 서버 환경변수 경로
- RPC 접두사 `deal_lunch_*`, 세션 `deal_lunch_session`, 명단 확인 쿠키 `deal_lunch_roster`를 사용할 구조
- 운영 Vercel의 `DEAL_INVITE_CODE=DEAL36`. 운영자 키는 명단을 받을 때 별도로 설정
- 명단과 DB가 없는 상태에서 활성화하지 않도록 서버 차단 및 예약 작업 제외 검증

현재 단계에서는 DEAL DB 테이블을 생성하거나 Group Node의 DB 본부 허용 목록을 변경하지 않습니다.
빈 본부 계정이나 가상의 인원을 만들지 않습니다.

## 명단 수신 후 개방 순서

1. 이름·소속 팀 목록을 확인하고 `lib/backend/deal-roster.ts`에 명단을 추가합니다. UUID는 `30000000-0000-4000-8000-...` 범위를 사용하고 가입 이후 변경하지 않습니다.
2. 동일 Supabase 프로젝트에 `deal_lunch_*` 테이블과 RPC를 신규 마이그레이션으로 추가합니다. 기존 테이블은 변경·복사하지 않습니다. 운영 종료일은 NULL, 22시 최초 편성·11시 마감·13시 결과 전환을 유지합니다.
3. 도시락만은 인원 제한 없는 도시락 묶음으로 분리하고, 나머지 일반 조는 최대 4명으로 편성합니다. 성비는 사용하지 않으며 팀 혼합 여부는 실제 팀 구성을 확인한 뒤 정합니다.
4. Group Node의 세션·명단·참여자·전체 본부 모임 연동에 DEAL을 추가합니다. 기존 본부 전용 글의 접근 범위를 유지합니다. 본부 관리자 계정도 기존 운영 정책에 맞춰 생성합니다.
5. 다른 본부와 겹치지 않는 32자 이상 `DEAL_ADMIN_SECRET`를 서버에 설정합니다. 별도 DB 접속 환경변수는 만들지 않습니다.
6. 가입·본부 격리·메뉴 편성·예약 작업·Group Node·관리자 권한을 전용 테스트 DB와 PC/모바일에서 확인한 후 명단과 코드를 배포해 개방합니다.

현재 단계에서 실행할 SQL은 없습니다. 실제 명단을 기준으로 마이그레이션을 만들어 배포합니다.
